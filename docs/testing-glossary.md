# Testing Glossary

| Term | Meaning |
|---|---|
| Bug / Defect | Behavior that differs from the requirement |
| Build | A packaged version of the software for testing |
| Regression | An existing feature that breaks after a change |
| Smoke test | Quick check of key functions on a new build |
| Sanity test | Narrow check of a specific change |
| RTM | Requirement Traceability Matrix |
| UAT | User Acceptance Testing |
| BVA | Boundary Value Analysis |
| EP | Equivalence Partitioning |
| Test case | Steps, data and expected result for one check |
| Test scenario | One-line description of what to test |
| Test suite | Group of test cases |
| Entry criteria | Conditions to start testing |
| Exit criteria | Conditions to stop testing |
| Severity | Technical impact of a defect |
| Priority | Urgency of the fix |
| Triage | Meeting to rate and assign new defects |
| Flaky test | Test that passes and fails without code changes |
| Hotfix | Urgent production fix |
| CI/CD | Continuous Integration and Delivery |
