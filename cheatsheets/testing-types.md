# Types of Testing Cheat Sheet

| Type | One line |
|---|---|
| Smoke | Quick check that the build's key functions work |
| Sanity | Narrow check after a small change or fix |
| Regression | Existing features still work after a change |
| Retesting | Re-run a failed test after a fix |
| Functional | Features work as required |
| Integration | Modules work together |
| System | Whole application against requirements |
| UAT | Users confirm it meets business needs |
| Performance | Speed and stability under load |
| Security | Protection against attacks and misuse |
| Usability | Easy and clear to use |
| Compatibility | Works across browsers, devices and OS |
| Exploratory | Learn and test at the same time |
| Ad hoc | Informal testing without a plan |

## Smoke vs Sanity
| | Smoke | Sanity |
|---|---|---|
| Scope | Broad, shallow | Narrow, deep |
| When | New build | After a fix or small change |
| Purpose | Is the build stable enough? | Does this change work? |

## Severity vs Priority
| | Severity | Priority |
|---|---|---|
| Meaning | Impact on the system | Urgency of the fix |
| Usually set by | Tester | Product owner or manager |
