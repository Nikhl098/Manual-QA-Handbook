# 02. SDLC and STLC

[Back to README](../README.md)

31 questions.

### Q1. What is SDLC?

Software Development Life Cycle: the phases a product goes through from idea to retirement - requirements, design, development, testing, deployment and maintenance.

### Q2. What are the phases of SDLC?

Requirement gathering, analysis, design, implementation (coding), testing, deployment and maintenance.

### Q3. What is STLC?

Software Testing Life Cycle: the sequence of testing activities - requirement analysis, test planning, test case design, environment setup, test execution and test closure.

### Q4. What happens in requirement analysis in STLC?

Testers study requirements to find testable items, ambiguities and gaps, and raise questions early.

### Q5. What happens in test planning?

The team defines scope, approach, effort estimate, roles, tools, schedule, risks and entry/exit criteria.

### Q6. What happens in test case design?

Testers write test cases and prepare test data, then get them reviewed.

### Q7. What happens in environment setup?

The test environment is prepared and a smoke test on the build confirms it is ready.

### Q8. What happens in test execution?

Test cases are run, results recorded, defects logged and retested after fixes.

### Q9. What happens in test closure?

Results are analyzed, a closure report is written, and lessons learned are documented.

### Q10. What is the difference between SDLC and STLC?

SDLC covers building the whole software. STLC covers only the testing activities inside it.

### Q11. What is the Waterfall model?

A linear model where each phase finishes before the next starts. Simple but inflexible to changing requirements.

### Q12. What are the pros and cons of Waterfall?

Pros: clear structure and documentation. Cons: late testing, hard to change requirements, working software appears late.

### Q13. What is the V-Model?

An extension of Waterfall where each development phase has a matching testing phase (requirements - acceptance testing, design - system testing, and so on).

### Q14. What is the Agile model?

An iterative approach delivering working software in short cycles with continuous feedback and collaboration.

### Q15. What is Scrum?

An Agile framework with fixed-length sprints, roles (Product Owner, Scrum Master, Team) and events (planning, daily standup, review, retrospective).

### Q16. What is Kanban?

A flow-based method using a board to visualize work and limit work in progress, without fixed sprints.

### Q17. What is the Spiral model?

A risk-driven model that repeats cycles of planning, risk analysis, engineering and evaluation.

### Q18. What is the Iterative model?

Software is built in repeated cycles, each adding more functionality on top of the last version.

### Q19. What is the Big Bang model?

Little planning; all code is integrated and tested at the end. Only suitable for tiny projects.

### Q20. What is the role of a tester in Agile?

Join planning and refinement, clarify acceptance criteria, test within the sprint, automate regression and work closely with developers.

### Q21. What is shift-left testing?

Starting testing activities earlier in the life cycle so defects are found sooner and cost less.

### Q22. What is CI/CD?

Continuous Integration merges and builds code often with automated tests. Continuous Delivery/Deployment automatically prepares or ships releases.

### Q23. What is a build?

A compiled, packaged version of the software that is given to testers.

### Q24. What is a release?

A build that has passed testing and is delivered to users.

### Q25. What is UAT?

User Acceptance Testing: the final check by real users or the client that the software meets business needs.

### Q26. What is alpha testing?

Testing by internal staff in a controlled environment before releasing to outsiders.

### Q27. What is beta testing?

Testing by a limited group of real users in the real environment before general release.

### Q28. What is the difference between alpha and beta testing?

Alpha is internal, at the developer's site or environment. Beta is external, with real users in their own environment.

### Q29. What is a hotfix?

An urgent fix for a critical production issue released outside the normal schedule.

### Q30. What is a patch?

A small update that fixes one or more defects or security issues.

### Q31. What is the difference between a build and a release?

A build is any compiled version produced in development. A release is a build officially delivered to users.
