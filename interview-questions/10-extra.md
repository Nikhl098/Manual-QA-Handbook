# 10. Extra Practice

[Back to README](../README.md)

16 questions.

### Q1. What is a negative test case example for a login page?

Entering a valid username with a wrong password and checking that an error message appears and no access is granted.

### Q2. What is a boundary test example for a password with 8 to 16 characters?

Test lengths 7, 8, 9, 15, 16 and 17. 7 and 17 should be rejected, and 8 and 16 should be accepted.

### Q3. What is a good expected result?

A specific, observable outcome such as "Error message 'Invalid password' is shown and the user stays on the login page".

### Q4. What is a test condition?

An item or event that could be checked by a test, such as a feature, rule or input.

### Q5. What is a precondition in a test case?

A state that must be true before the test starts, such as the user being registered.

### Q6. What is a postcondition in a test case?

The state the system should be in after the test ends, such as the order saved in the database.

### Q7. What does it mean when a test case is passed, failed, blocked and not run?

Passed: actual matches expected. Failed: it does not. Blocked: cannot be executed. Not run: not yet executed.

### Q8. What is a build verification test (BVT)?

Another name for a smoke test on a new build to check that it is stable enough to test.

### Q9. What is tester bias?

The tendency to test only what you expect to work. Fresh eyes, peer review and exploratory testing reduce it.

### Q10. What is peer review of test cases?

Another tester or the BA reviews your test cases to find gaps, errors and unclear steps.

### Q11. What is the difference between a bug report and a test report?

A bug report describes one defect. A test report summarizes the results of a testing effort.

### Q12. What are the common reasons for defects?

Unclear requirements, design mistakes, coding errors, missing validation, changing requirements, tight deadlines and poor communication.

### Q13. What are the common test deliverables?

Test plan, test cases, test data, RTM, defect reports, test summary report and automation scripts if any.

### Q14. What is a retrospective action item?

A concrete improvement the team agrees to try after a retrospective, with an owner.

### Q15. What is a regression defect?

A bug that appears in an existing feature because of a new change.

### Q16. How do you verify an email feature?

Check recipient, subject, body, links, attachments, formatting, delivery time, spam folder behavior and unsubscribe or reply handling.
